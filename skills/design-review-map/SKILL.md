# Дизайн-ревью стопкой

Результат — страница со стопкой скриншотов. По каждому экрану владелец решает:

- **«Принять»** — свайп вправо, кнопка или клавиша →;
- **«Доработать»** — свайп влево, кнопка или клавиша ←. Открывается форма, поле заметки сразу в фокусе. Нажатие на макет ставит точку 1, 2, 3, поле переключается на неё. Под полем готовые фразы («Крупнее», «Сдвинуть»). Enter отправляет, Shift + Enter переносит строку.

Поле стоит в верхней половине экрана, под макетом, шрифт 16 px, страница не прокручивается. Поэтому клавиатура телефона ничего не перекрывает и не сдвигает, а макет виден над полем. На телефоне клавиатура открывается сразу: диктуют её микрофоном, на Windows — Win + H. Своей кнопки микрофона у страницы нет: приложение Claude не даёт артефакту доступ к микрофону.

Скриншот можно рассмотреть: нажатие на него или на лупу открывает его на весь экран, там увеличивают щипком, двойным нажатием, колесом мыши или кнопками «−» и «+», закрывают крестиком, Esc или движением вниз. На телефоне можно сразу развести два пальца на карточке: скриншот поднимается на весь экран и растёт под пальцами; если свести пальцы обратно, он вернётся в карточку. В форме «Доработать» скриншот тоже увеличивается щипком или колесом, точка ставится туда, куда нажали. Длинный скриншот страницы целиком листается внутри карточки и открывается по ширине. Длинное название или описание обрезается, «Ещё» раскрывает его целиком.

В меню «⋯»: «Скопировать решения», «Скачать решения» (вне артефакта), «Сбросить решения» и где сейчас хранятся решения. Когда все экраны решены, появляется экран итогов.

**Когда:** нужно решение владельца по виду экранов: макеты дизайнера или исполнителя, скриншоты собранного интерфейса, «до и после». От 2 экранов. Решения по тексту ревью (код, аудит, тексты) — скилл `review-checklist`.

Работает в Claude (claude.ai, приложение, Cowork) и в агентах без артефактов — Codex, Claude Code. Отличается только то, как показать страницу и откуда забрать решения.

## Файлы скилла

Пути — от папки этого скилла.

- `scripts/build.py` — собирает страницу, список экранов и markdown-копию из `spec.json`.
- `scripts/collect.py` — сводит решения с экранами и пишет раздел «Решения владельца».
- `scripts/serve.py` — локальный сервер: страница плюс автосохранение решений в файл.
- `assets/template.html` — шаблон страницы.
- `assets/example-spec.json` и папка `assets/example/` — пример: пять экранов Chatgun.
- `references/spec.md` — формат `spec.json`, решений и скопированного текста.

Скрипты — только стандартная библиотека Python 3.8+. На Windows вместо `python3` — `py -3` или `python`.

## Порядок

1. **Скриншоты.** Файлы PNG, JPEG, WebP, GIF или SVG, по одному на экран.
   - Макеты — как есть.
   - Собранный интерфейс — снять, если есть Playwright: телефон 390×844 с `deviceScaleFactor: 2`, компьютер 1440×900. Без сети шрифты могут не загрузиться — посмотреть снимки глазами.
   - Страницу целиком можно снять одним длинным скриншотом (`fullPage`): на карточке он листается.
   - Разрешение не уменьшать: скриншоты увеличивают. Тяжёлые PNG сжать в WebP или JPEG с качеством 80–85.
   - Состояния (пустое, ошибка, тёмная тема) — отдельными экранами.
2. **spec.json.** Записать экраны по `references/spec.md`; образец — `assets/example-spec.json`. Пути к картинкам — от папки `spec.json`. Правила текстов — ниже, в «Как подписывать экраны».
3. **Сборка:** `python3 <скилл>/scripts/build.py spec.json OUT`. Получатся `OUT/<key>.html`, `OUT/<key>-screens.json`, `OUT/<key>.md`.
   - По умолчанию скриншоты лежат внутри страницы, это один файл. Больше 8 МБ — предупреждение, больше 15 МБ — ошибка.
   - `--images copy` кладёт скриншоты рядом, в `OUT/<key>-img/`, и пишет `OUT/<key>-files.json` — карту файлов для публикации артефакта. Брать, когда скриншотов много или они тяжёлые.
4. **Проверка — один раз:**
   - вырезать `<script>` без атрибутов из страницы в файл и `node --check`, если есть Node;
   - если есть Playwright: 390×844 и 1280×800, `document.documentElement.scrollWidth` равен ширине окна, картинки загрузились (`naturalWidth > 0`), без ошибок страницы; ошибки загрузки шрифтов без сети не в счёт;
   - посмотреть снимок и поправить один раз, без цикла.
5. **Показать страницу** — по окружению, см. ниже.
6. **Markdown-копию** `OUT/<key>.md` положить туда, где проект держит документы: проект claude.ai, папка в репозитории — по правилам проекта.
7. **Ответ в чат:** 1–2 фразы о том, что на ревью, затем «Пролистайте экраны и напишите „готово“». Экраны не пересказывать.

### Claude с инструментом Artifact

`OUT` — рабочая папка (scratchpad).

1. Загрузить скилл `artifact-capabilities`: без него `capabilities` передавать нельзя.
2. `Artifact` publish:
   - `file_path` = `OUT/<key>.html`;
   - `icon: "image"`;
   - `description` — одно предложение;
   - `capabilities: {"db": {}, "user": {}}`;
   - со сборкой `--images copy` ещё `files` — содержимое `OUT/<key>-files.json`.
3. Один `ArtifactData` `list` коллекции `decisions` — должна быть пустой.
4. Пересобрать с `--url <ссылка артефакта>`, чтобы ссылка попала в markdown-копию. Страница от этого не меняется, публиковать её заново не нужно.
5. Ссылку в ответе не повторять — карточка артефакта уже видна.

Решения пишутся в хранилище артефакта сразу. На телефоне и компьютере владельца видно одно и то же: экран, решённый на одном устройстве, на другом уходит из стопки.

### Codex, Claude Code и другие агенты без Artifact

`OUT` — папка в проекте:

- если в проекте есть место для ревью (`AGENTS.md`, `CLAUDE.md`, папка `review/`, `design/` или `plans/`), то туда;
- иначе `design-review/<key>/` в рабочей папке.

Не коммитить эти файлы, если владелец не просил.

Два способа показать страницу — предложить оба, по умолчанию первый:

1. **Файл в браузере.**
   - Дать полный путь к `OUT/<key>.html` и открыть его: Windows — `start "" "<путь>"`, macOS — `open`, Linux — `xdg-open`.
   - Решения хранятся в этом браузере.
   - В конце владелец нажимает «Скопировать решения» и вставляет текст в чат или «Скачать решения» и говорит, где файл.
2. **С автосохранением в файл.**
   - Владелец запускает в отдельном терминале `python3 <скилл>/scripts/serve.py OUT`. Сервер работает, пока его не остановят, — не запускать его так, чтобы он занял свою сессию.
   - Страница — по адресу, который выведет сервер: `http://127.0.0.1:8765/<key>.html`.
   - Каждое действие сразу пишется в `OUT/<key>-decisions.json`.
   - Сервер слушает только этот компьютер, с телефона страница так не откроется.

## Когда владелец написал «готово»

1. **Взять решения:**
   - Claude с Artifact: `ArtifactData` `list`, `collection: "decisions"`, `out_dir: OUT/dec`. Файлы лягут в `OUT/dec/decisions/<id>.json`, передать эту папку.
   - Сервер: `OUT/<key>-decisions.json`.
   - Кнопка «Скачать решения»: путь к файлу назовёт владелец.
   - Текст из «Скопировать решения»: сохранить в файл и передать его.
2. **Свести:** `python3 <скилл>/scripts/collect.py OUT/<key>-screens.json <решения> --md OUT/<key>.md`. Выведет сводку: «На доработку» с заметками и точками, «Принято», «Без решения» — и заменит раздел «Решения владельца» в копии. Обновлённую копию положить туда же, куда в шаге 6.
3. **Точки — в слова.** Открыть скриншот (путь и размер есть в сводке) и назвать элемент под каждой точкой. `x` и `y` — доли ширины и высоты от левого верхнего угла. Например, «Точка 1 (x 30%, y 22%): Сдвинуть» на экране 390×844 — это около 117×186 px: «Точка 1, карточка „Подписчики“: сдвинуть». Если под точкой неясно что, оставить координаты и спросить.
4. **Следующий шаг** — промпт исполнителю, задача дизайнеру или правки:
   - в работу идут только экраны «На доработку», по заметкам владельца; фразы и темы — его слова, не расширять их;
   - к каждому экрану — путь к скриншоту, точки с координатами и названием элемента;
   - «На доработку» без заметок — спросить, что не так;
   - «Принято» перечислить в разделе «Не менять», чтобы исполнитель не взялся сам;
   - «Без решения» не включать — спросить;
   - вопросы собрать в одно короткое сообщение;
   - рекомендация без ответа — не согласие; ничего не добавлять от себя.

## Как подписывать экраны

- **title** — название экрана словами продукта: «Главная», «Новая рассылка, пустое состояние». До 40 знаков, в одну строку на телефоне.
- **note** — одно предложение до 140 знаков: что изменилось и на что смотреть. Длиннее — на карточке видны две строки, остальное под «Ещё»; `build.py` предупредит. Подробности — в `intro`, он попадает в markdown-копию. Без оценок вроде «стало лучше». Нечего сказать — не заполнять.
- **Порядок** — как человек идёт по продукту. Телефон и компьютер можно смешивать.
- **Коды** — `prefix` и номер: Э1, Э2. Буква не должна повторять коды других ревью проекта.
- **phrases** — по умолчанию общие. Для ревью можно задать свои, например «Как в Figma» или «Контраст»: одно-два слова, до 10 штук.
- **tags** — по умолчанию нет: о чём заметка, видно из текста. Заданные встают в ряд с фразами для всего экрана.
- **heading** — шапка страницы, одно-два слова. Длинное название ревью — в `title`.

## Правки после публикации

- **`id` экрана — ключ решения:** `s1`, `s2` и дальше по порядку в `screens`.
  - Не менять порядок уже показанных экранов.
  - Новые экраны — только в конец списка.
  - Снятый экран не удалять — дописать в `title` «(снят)».
- **Новая версия после доработки** — новое ревью с новым `key`. В `note` — что исправлено по прошлым заметкам.
- **Claude с Artifact:**
  - пересобрать и опубликовать тот же `file_path` — ссылка останется прежней;
  - `icon` и `capabilities` при повторной публикации не передавать;
  - из другого разговора — сначала `Artifact` `read` по ссылке, потом publish с `url`;
  - страница закрыта, открыть её другим людям владелец может через «Поделиться».
- **Локально:** пересобрать в ту же папку и обновить страницу в браузере. Решения сохранятся: ключ хранилища — `key`.

Тексты страницы — русские. Для другого языка перевести постоянные строки в `assets/template.html` и `scripts/build.py`.
