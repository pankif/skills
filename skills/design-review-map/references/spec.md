# Формат spec.json и решений

Пример целиком — `assets/example-spec.json`.

```json
{
  "title": "Дизайн-ревью Chatgun: мобильное приложение и кабинет",
  "heading": "Дизайн-ревью",
  "key": "chatgun-design",
  "prefix": "Э",
  "intro": "Новые экраны мобильного приложения и первая версия дашборда веб-кабинета.",
  "phrases": ["Крупнее", "Мельче", "Сдвинуть", "Выровнять", "Другой цвет", "Убрать", "Опечатка", "Не по сетке"],
  "screens": [
    {"image": "example/01-home.svg", "title": "Главная", "note": "Новый блок аналитики сверху."},
    {"image": "shots/dashboard.webp", "title": "Дашборд", "w": 1440, "h": 900}
  ]
}
```

## Поля

| Поле | Обязательно | Что это |
|---|---|---|
| `title` | да | Название ревью: заголовок вкладки и markdown-копии. |
| `heading` | нет | Шапка страницы, одно-два слова. По умолчанию «Дизайн-ревью». |
| `key` | да | Латиница, цифры, `_` и `-`. Имя файлов и ключ хранилища решений в браузере. |
| `prefix` | нет | Буква кодов экранов: Э1, Э2. По умолчанию «Э». |
| `intro` | нет | Абзац в начале markdown-копии. На странице не показывается. |
| `phrases` | нет | Готовые фразы для точки и для всего экрана. По умолчанию — как в примере. |
| `tags` | нет | Темы для всего экрана, в одном ряду с фразами. По умолчанию нет. |
| `screens` | да | Экраны в порядке показа. |

Поля экрана:

| Поле | Обязательно | Что это |
|---|---|---|
| `image` | да | Путь к PNG, JPEG, WebP, GIF, AVIF или SVG — от папки `spec.json` или абсолютный. |
| `title` | да | Название экрана. |
| `note` | нет | Одно предложение: что изменилось и на что смотреть. |
| `w`, `h` | нет | Размер в пикселях. `build.py` читает его из файла сам; для AVIF и SVG без размеров — указать. |

`id` и код экрана `build.py` выдаёт сам: `s1`, `s2` и `Э1`, `Э2` по порядку в `screens`.

## Что пишет build.py

- `<key>.html` — страница. Данные лежат в `<script id="review-data" type="application/json">`.
- `<key>-screens.json` — список экранов: `[{id, code, title, note, image, w, h}]`. Его читает `collect.py`.
- `<key>.md` — копия для проекта: таблица экранов и раздел «## Решения владельца».
- С `--images copy`: папка `<key>-img/` со скриншотами `01.png`, `02.webp`… и `<key>-files.json` — `{"<key>-img/01.png": "<полный путь>"}`, готовый параметр `files` для `Artifact`.
- С `--url` ссылка на страницу попадает в markdown-копию.

## Решение по экрану

Одинаково в хранилище артефакта (`decisions/<id>`), в `<key>-decisions.json` от `serve.py` и в файле «Скачать решения» (там ещё `code` и `title`):

```json
{
  "s2": {
    "status": "fix",
    "comment": "Подпись ближе к карточке",
    "tags": [],
    "phrases": ["Выровнять"],
    "pins": [
      {"x": 0.2957, "y": 0.2181, "text": "", "phrases": ["Сдвинуть"]},
      {"x": 0.6989, "y": 0.5993, "text": "Тень слабее", "phrases": []}
    ],
    "at": "2026-10-22T09:59:40.276Z"
  }
}
```

- `status`: `ok` — принято, `fix` — на доработку, пустая строка — без решения.
- `comment`, `tags`, `phrases` — заметка ко всему экрану.
- `pins` — точки по порядку номеров. `x` и `y` — доли ширины и высоты скриншота от левого верхнего угла, от 0 до 1.
- Пока форма доработки открыта, черновик тоже сохраняется, со статусом без изменений.

## Текст «Скопировать решения»

Блоки через пустую строку, первая строка блока — код, название и решение:

```
Э1 Главная: принято

Э2 Список сценариев: доработать
Весь экран: Выровнять. Подпись ближе к карточке
Точка 1 (x 30%, y 22%): Сдвинуть
Точка 2 (x 70%, y 60%): Тень слабее

Э3 Новая рассылка: без решения
```

`collect.py` читает этот текст так же, как файлы решений.
