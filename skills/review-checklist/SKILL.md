# Интерактивный чек-лист ревью

Превращает итоги ревью в страницу с решениями. Владелец отмечает пункты на странице, а не пишет полотно в чат; агент потом читает решения и делает следующий шаг только из согласованного.

**Когда:** ревью ветки или кода, проверка чужой работы (например коммитов исполнителя по промпту), аудит дизайна или текстов — список от 6 предложений, по которым нужно решение владельца. Если пунктов 3–5 — проще спросить в чате.

Работает в Claude (claude.ai, приложение, Cowork) и в агентах без артефактов — Codex, Claude Code. Отличается только то, как показать страницу и откуда забрать решения.

## Файлы скилла

Пути — от папки этого скилла.

- `scripts/build.py` — собирает страницу, список пунктов и markdown-копию из `spec.json`.
- `scripts/collect.py` — сводит решения с пунктами и пишет раздел «Решения владельца».
- `scripts/serve.py` — локальный сервер: страница плюс автосохранение решений в файл.
- `assets/template.html` — шаблон страницы.
- `assets/example-spec.json` — пример входных данных.
- `references/spec.md` — формат `spec.json`, поле за полем.

Скрипты — только стандартная библиотека Python 3.8+. На Windows вместо `python3` — `py -3` или `python`.

## Порядок

1. **Ревью.** Сначала сделать саму работу и собрать пункты. Страницу — только когда пункты готовы.
2. **spec.json.** Записать пункты по `references/spec.md`; образец — `assets/example-spec.json`. Правила текстов — ниже, в «Как писать пункты».
3. **Сборка:** `python3 <скилл>/scripts/build.py spec.json OUT`. Получатся `OUT/<key>.html`, `OUT/<key>-items.json`, `OUT/<key>.md`.
4. **Проверка — один раз:**
   - вырезать `<script>` без атрибутов из страницы в файл и `node --check`, если есть Node;
   - если есть Playwright: 1280 px светлая и 390 px тёмная, `document.documentElement.scrollWidth` равен ширине окна, без ошибок страницы; ошибки загрузки шрифтов без сети не в счёт;
   - посмотреть результат и поправить один раз, без цикла.
5. **Показать страницу** — по окружению, см. ниже.
6. **Markdown-копию** `OUT/<key>.md` положить туда, где проект держит документы: проект claude.ai, папка в репозитории — по правилам проекта.
7. **Ответ в чат:** 1–2 фразы итога, самые важные пункты списком по одному предложению, затем «Отметьте пункты на странице и напишите „готово“».

### Claude с инструментом Artifact

`OUT` — рабочая папка (scratchpad).

1. Загрузить скилл `artifact-capabilities`: без него `capabilities` передавать нельзя.
2. `Artifact` publish:
   - `file_path` = `OUT/<key>.html`;
   - `icon: "checklist"`;
   - `description` — одно предложение;
   - `capabilities: {"db": {}, "user": {}}`.
3. Один `ArtifactData` `list` коллекции `decisions` — должна быть пустой.
4. Пересобрать с `--url <ссылка артефакта>`, чтобы ссылка попала в markdown-копию.
5. Ссылку в ответе не повторять — карточка артефакта уже видна.

Решения пишутся в хранилище артефакта сразу, на любом устройстве владельца.

### Codex, Claude Code и другие агенты без Artifact

`OUT` — папка в проекте:

- если в проекте есть место для ревью (`AGENTS.md`, `CLAUDE.md`, папка `review/` или `plans/`), то туда;
- иначе `review-checklist/<key>/` в рабочей папке.

Не коммитить эти файлы, если владелец не просил.

Два способа показать страницу — предложить оба, по умолчанию первый:

1. **Файл в браузере.**
   - Дать полный путь к `OUT/<key>.html` и открыть его: Windows — `start "" "<путь>"`, macOS — `open`, Linux — `xdg-open`.
   - Решения хранятся в этом браузере.
   - В конце владелец нажимает «Скопировать решения» и вставляет текст в чат или «Скачать решения» и говорит, где файл.
2. **С автосохранением в файл.**
   - Владелец запускает в отдельном терминале `python3 <скилл>/scripts/serve.py OUT`. Сервер работает, пока его не остановят, — не запускать его так, чтобы он занял свою сессию.
   - Страница — по адресу, который выведет сервер: `http://127.0.0.1:8765/<key>.html`.
   - Каждое решение сразу пишется в `OUT/<key>-decisions.json`.

## Когда владелец написал «готово»

1. **Взять решения:**
   - Claude с Artifact: `ArtifactData` `list`, `collection: "decisions"`, `out_dir: OUT/dec`. Файлы лягут в `OUT/dec/decisions/<id>.json`, передать эту папку.
   - Сервер: `OUT/<key>-decisions.json`.
   - Кнопка «Скачать решения»: путь к файлу назовёт владелец.
   - Текст из «Скопировать решения»: сохранить в файл и передать его.
2. **Свести:** `python3 <скилл>/scripts/collect.py OUT/<key>-items.json <решения> --md OUT/<key>.md`. Выведет сводку по группам и заменит раздел «Решения владельца» в копии. Обновлённую копию положить туда же, куда в шаге 6.
3. **Следующий шаг** — промпт исполнителю, план или правки:
   - в работу идёт только «Делаем»; комментарий владельца главнее текста «Предлагаю»;
   - «Обсудить» и «Без решения» не включать — спросить одним коротким сообщением;
   - «Не делаем» перечислить в разделе «Не делаем» следующего промпта, чтобы исполнитель не взялся сам;
   - рекомендация без ответа — не согласие; ничего не добавлять от себя.

## Как писать пункты

- **Заголовок** — что видит человек, а не механизм: «Рассылка может навсегда остаться „Запущена“», а не «ошибка SetStarted игнорируется».
- **Что не так** — когда случается, что видно пользователю, чем грозит. Старую ошибку, найденную рядом, помечать: «Было и до правок».
- **Предлагаю** — один конкретный шаг. Несколько вариантов — выбрать один.
- **Где** — `путь:строки`, несколько мест через `; `.
- Простой язык, без жаргона там, где можно без него. Без «успешно», восклицаний и вводных.
- **Важность:**
  - 3 — деньги, данные, безопасность или ломается у многих;
  - 2 — заметный сбой в частом сценарии или зависание без выхода;
  - 1 — редкий случай, косметика, чистота кода.
- **Точность:** «проверено» — видно по коду или воспроизведено; «вероятно» — вывод без запуска.
- **Объём:** S — до часа, M — до дня, L — больше.
- **Коды** уникальны среди ревью проекта:
  - одна буква на всё ревью (`prefix`) или своя у каждой области (`areas[].prefix`);
  - буква — та, что не занята прошлыми ревью проекта.
- **Порядок в `items`** — по областям, внутри области от важного к мелкому. Номера и `id` идут по этому порядку.

## Правки после публикации

- **`id` пункта — ключ решения.**
  - Не менять порядок и область уже показанных пунктов.
  - Новые пункты — только в конец списка.
  - Снятый пункт не удалять — дописать в заголовок «(снят)».
- **Claude с Artifact:**
  - пересобрать и опубликовать тот же `file_path` — ссылка останется прежней;
  - `icon` и `capabilities` при повторной публикации не передавать;
  - из другого разговора — сначала `Artifact` `read` по ссылке, потом publish с `url`;
  - страница закрыта, открыть её другим людям владелец может через «Поделиться».
- **Локально:** пересобрать в ту же папку и обновить страницу в браузере. Решения сохранятся: ключ хранилища — `key`.

Тексты страницы — русские. Для другого языка перевести постоянные строки в `assets/template.html` и `scripts/build.py`.
