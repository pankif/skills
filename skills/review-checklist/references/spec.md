# Формат spec.json

Пример целиком — `assets/example-spec.json`.

```json
{
  "title": "Проверка серверных правок",
  "key": "sfix",
  "eyebrow": ["<b>my-server</b>", "57e757b → 95505a0 · 12 коммитов"],
  "intro": "Исполнитель сделал всё, что было в промпте. Ниже — что нашлось при проверке.",
  "verdict": [
    {"label": "Сделано по промпту", "html": "<p class=\"vbig\"><b>42 из 42</b> пунктов</p><p>Прогоны зелёные.</p>"},
    {"label": "Иначе, чем в промпте, — принимаю", "html": "<ul><li><b>С1</b> превью заполняется в GET</li></ul>"}
  ],
  "findingsTitle": "Что нашёл",
  "md_intro": "## Итог\n\nВсе пункты промпта сделаны.",
  "prefix": "Д",
  "areas": [{"id": "broad", "name": "Рассылки"}, {"id": "tests", "name": "Тесты и CI"}],
  "placeholder": "Например: только сервер, клиент — потом",
  "foot": "Пункты собраны по чтению кода. «Вероятно» — вывод без запуска. Объём: S — до часа, M — до дня, L — больше.",
  "items": [
    {"area": "broad", "sev": 2, "cat": "Надёжность", "effort": "M", "conf": "проверено",
     "title": "…", "problem": "…", "fix": "…", "where": "internal/broadcasting/pending_launcher.go:59-90"}
  ]
}
```

## Поля

| Поле | Обязательно | Что это |
|---|---|---|
| `title` | да | Название страницы и вкладки: 2–4 слова, без пояснения через тире |
| `key` | да | Латиница, цифры, `_`, `-`. Имя файлов и ключ хранилища в браузере. После показа не менять |
| `areas` | да | Области в порядке показа: `{id, name, prefix?}`. `id` — латиница |
| `prefix` | да, если у областей нет своих | Буква кодов на всё ревью: `Д` → Д1, Д2… |
| `items` | да | Пункты, см. ниже |
| `eyebrow` | нет | Строка над заголовком: репозиторий, ветка, диапазон коммитов. HTML |
| `intro` | нет | Одна-две фразы перед инструкцией «выберите…». HTML |
| `verdict` | нет | Блок итога над списком, 2–3 колонки `{label, html}`. Для проверки чужой работы: что сделано, какие отступления принимаю, что упало |
| `findingsTitle` | нет | Заголовок над списком, когда есть `verdict`. По умолчанию «Пункты» |
| `md_intro` | нет | Markdown для копии перед таблицей пунктов: итог, отступления, прогоны |
| `placeholder` | нет | Подсказка в поле комментария |
| `foot` | нет | Сноска внизу: как собраны пункты, что значат объёмы. HTML |

HTML-поля вставляются как есть, остальное экранируется. Внутри `verdict` доступны классы `vbig` — крупная строка с зелёным `<b>` — и списки `<ul>`, где `<b>` — моноширинный код пункта.

## Пункт

| Поле | Значения |
|---|---|
| `area` | `id` области |
| `sev` | 3 — высокая, 2 — средняя, 1 — низкая |
| `cat` | Короткое слово: Ошибка, UX, Надёжность, Безопасность, Код, Тесты, Тексты, Производительность |
| `effort` | `S` — до часа, `M` — до дня, `L` — больше |
| `conf` | `проверено` или `вероятно` |
| `title` | Что видит человек, одна строка |
| `problem` | Что не так: когда, что видно, чем грозит |
| `fix` | Один конкретный шаг |
| `where` | `путь:строки`, несколько — через `; ` |

## Коды и id

- Своя буква у области (`areas[].prefix`): коды Р1, Р2… внутри области, `id` — `<area><n>`.
- Иначе общий `prefix`: коды Д1, Д2… по всему списку, `id` — `i<n>`.
- Номера идут по порядку в `items`. Решения хранятся по `id`, поэтому после показа порядок не меняют, новые пункты добавляют в конец.

## Что получается

- `OUT/<key>.html` — страница.
- `OUT/<key>-items.json` — пункты с кодами и `id`, вход для `collect.py`.
- `OUT/<key>.md` — markdown-копия: таблица, подробности, раздел «Решения владельца».
- `OUT/<key>-decisions.json` — решения, если страница открыта через `serve.py`. Тот же формат у файла из кнопки «Скачать решения».
