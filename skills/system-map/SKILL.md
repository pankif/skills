# Карта системы

Результат — автономная HTML-карта и JSON-модель. Слева каталог областей и сценариев, в центре вся выбранная схема, справа объяснение элемента или связи. Внешний вид: тёмный синий холст, смысловые стрелки, выделение пути, раскрываемые основания и замечания для агента.

Скилл разбирает **существующую реализацию**. Названия и правила системы берутся из исследуемого проекта. Проектирование будущей реализации требует отдельного запроса и явного обозначения проектных решений.

Работает в Codex, Claude Code и Claude с доступом к файлам и Python 3.8+. Сборка использует стандартную библиотеку; готовая страница работает без сети и внешних JS-библиотек.

## Файлы

Пути ниже — от папки скилла, в командах она обозначена `<skill>`.

- `references/analysis.md` — прочитать перед исследованием: границы, прослеживание сценариев, смысл доказательств и обновление карты.
- `references/model.md` — прочитать перед записью JSON: формат, уровни, типы элементов и источники.
- `scripts/build_map.py` — проверка модели, извлечение точных фрагментов и сборка HTML.
- `assets/map-template.html` — готовый интерфейс. Менять только по запросу на интерфейс; для новой системы достаточно другой модели.
- `assets/example.json` и `assets/example-project/app.py` — вымышленный пример формата и исходники к нему. Их сущности не переносить в пользовательский проект.

## Порядок работы

### 1. Определить область и источники

Найти реальный workspace, прочитать его правила и точку входа в документацию. Выяснить, какие репозитории участвуют в запрошенной области. Если проект или фича названы, начинать с них; уточнять только то, без чего нельзя выбрать предмет разбора.

Выписать границы анализа: что исследуется, чего нет среди доступных данных, какой checkout используется, есть ли локальные изменения. Документацию и память использовать для поиска кода, а спорные утверждения сверять с текущей реализацией. Применять правила из `references/analysis.md`.

**Готово:** определены источники и область, а доступная реализация найдена. Если исходников нет, явно ограничить карту предоставленными материалами.

### 2. Проследить поведение

Сначала найти точки входа, сборку зависимостей, основную логику и хранилища. Затем проследить конкретные сценарии от триггера до наблюдаемого результата, включая существенные условия и альтернативные исходы. Для выбранной фичи проверить фоновые задачи, события и внешние системы, влияющие на её поведение.

Для каждого утверждения о поведении и каждой стрелки сохранить адрес основания: источник, файл и строки. Проверять именно описываемую связь; соседство файлов и совпадение имён не доказывают вызов. Тесты, конфигурация, документация и наблюдения подтверждают разные виды утверждений — учитывать их пределы.

**Готово:** у отображаемых фактов есть основания; непрослеженные переходы и предположения названы явно. Сборка проверяет наличие ссылок, смысл выводов проверяет агент.

### 3. Разложить на карты и написать модель

По `references/model.md` создать JSON с `schemaVersion: 1`.

Использовать нужные уровни одной модели:

- **Обзор:** ответственность модулей и основные связи, чтобы понять устройство области.
- **Сценарий:** что происходит после конкретного действия, какие данные меняются и чем заканчивается каждый существенный путь.
- **Логика:** условия, состояния, расчёты, ошибки, повторы и компенсации, требующие отдельного разбора.

Для узкой задачи достаточно одного уровня. Для большой системы связывать обзор с картами областей, а те — со сценариями и логикой через `scenario` и `related`. Вся выбранная схема видна сразу; детали раскрываются без обязательного пошагового прохождения.

На узлах — короткие понятные названия, в инспекторе — технические имена и объяснения. У стрелки — действие или условие («пишет», «публикует», «остаток достаточен»). Разделять синхронный вызов, асинхронную доставку и связь по данным в описании. Язык интерфейса по умолчанию русский, имена из кода сохраняются.

Начать с сетки до трёх колонок и четырёх слоёв. Плотную область вынести во вложенную карту. Это ориентир читаемости, а не ограничение предмета или числа карт.

**Готово:** JSON описывает запрошенную область, содержит проверяемые факты и явно отмеченные границы; id устойчивы для следующих обновлений.

### 4. Проверить и собрать

Папку результата выбрать по правилам проекта; иначе — `system-map/` в рабочей папке. Один `--root` связывает id источника с его локальной папкой. Для нескольких репозиториев повторить аргумент.

```bash
python3 <skill>/scripts/build_map.py data/model.json --root backend=/path/to/backend --root frontend=/path/to/frontend --check
python3 <skill>/scripts/build_map.py data/model.json --root backend=/path/to/backend --root frontend=/path/to/frontend -o system-map/map.html
```

На Windows использовать `python` или `py -3`, пути с пробелами заключать в кавычки: `--root "backend=C:\work\my project"`.

Сборщик снимает только указанные диапазоны, записывает хеши файлов, версии Git и ссылки на точные коммиты GitHub. Изменённый или незакоммиченный файл получает локальный снимок. Другие Git-хостинги и папки без Git работают с фрагментами и хешами, без автоматических ссылок.

Рядом с `map.html` появится `map.json` с теми же картами и приложенными основаниями. Его можно пересобрать без доступа к исходникам; это сохранённый снимок, а не новый разбор текущего кода. Для обновления передать `--root` и перепроверить изменившиеся выводы.

Посмотреть готовую страницу в доступном браузере. Проверить все представления: вся схема помещается, подписи и стрелки читаемы, нет пересечений, меняющих смысл, навигация и поиск работают. Проверить узел, связь, раскрытие основания, вложенный переход, замечание и копирование для агента. Если браузера нет, обозначить, что визуальная проверка не выполнена.

**Готово:** проверка модели проходит; при доступном браузере проверены интерфейс и читаемость. Тесты приложения запускать, только когда это требуется для подтверждения конкретного вывода; отмечать, что читалось, а что действительно запускалось.

### 5. Показать результат

- **Обычный браузер, Codex или Claude Code:** отдать HTML и JSON с полными путями. HTML открывается как файл.
- **Codex со встроенной визуализацией:** по доступному в окружении механизму показать фрагмент, собранный с `--fragment`. Инструкции механизма загрузить перед использованием; автономный HTML сохранить отдельно.
- **Claude с Artifact:** показать автономный HTML доступным инструментом артефактов; JSON оставить файлом для обновления.

Коротко назвать охват и существенные границы анализа. Детали уже находятся на карте. Публикация во внешний сервис или коммит в исследуемый проект выполняются по запросу пользователя.

## Обновления и замечания

Человек выбирает узел или связь, добавляет замечание и нажимает «Скопировать для агента». Замечания сохраняются локально в браузере, а в поддерживаемом встроенном просмотре — также в состоянии виджета. Если окружение запрещает сохранение, скопировать замечания до закрытия страницы. Автономная страница не делает сетевых запросов.

По полученному тексту прочитать существующую модель, проверить замечания по текущим источникам и изменить относящиеся к ним карты. Сохранять `snapshot.key`, id карт и сохранившихся сущностей: это ключи замечаний. Изменившиеся источники снимать заново; после сдвига строк заново найти нужный символ. Старое основание не подтверждает изменившийся вывод. Затем повторить сборку и проверку затронутых карт.

Значения секретов в HTML и JSON не переносить. Для чувствительного файла указать `redact: true` и причину в `note`; в результат попадут адрес, хеш и пометка скрытого содержимого.
