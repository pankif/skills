# Формат модели system-map v1

Начать с `assets/example.json`. Это маленькая вымышленная система; её фрагменты снимаются из `assets/example-project/app.py`.

```bash
python3 <skill>/scripts/build_map.py <skill>/assets/example.json --root demo=<skill>/assets/example-project -o out/example.html
```

## Корень

| Поле | Смысл |
|---|---|
| `schemaVersion` | Число `1` |
| `defaultView` | id первой карты, произвольный |
| `snapshot` | Имя, идентификатор, дата, область и источники |
| `sources` | Объект `id → адрес основания` |
| `views` | Объект `id → карта` |

id — строчная латиница, цифры, `.`, `_`, `-`; первый знак — буква или цифра. id узла или связи уникален внутри своей карты. В интерфейсе он не заменяет понятное название.

## snapshot

Обязательные строки: `key` (устойчивый id карты для замечаний), `name`, `date` (дата анализа), `scope` (что исследовано и пределы проверки). Необязательные: `subtitle`, `note`.

`repositories` — массив источников. Для каждого: `id`, `name`, необязательно `tech`. Это может быть репозиторий либо папка документов или логов. Локальные пути передаются только через `--root ID=PATH` и не записываются в результат.

При доступном Git сборщик дописывает `head`, `branch`, `dirty`, `url`. `capturedAt` — время последней сборки оснований; оно не заменяет дату анализа. Без Git и без `--root` версия может остаться неизвестной. Повторная офлайн-сборка сохраняет сведения о времени снятия исходного снимка.

## sources

```json
{
  "submit-handler": {
    "repo": "backend",
    "path": "src/reports.py",
    "start": 12,
    "end": 30,
    "kind": "code"
  }
}
```

`path` — относительный путь внутри соответствующего `--root`, с `/`. Строки с единицы, обе границы включены. Диапазон должен существовать целиком. Сборщик сам копирует строки в `code`; переписывать фрагмент своими словами нельзя.

`kind`: `code`, `config`, `docs`, `test`, `runtime`, `user`, `example`. Для наблюдений и сведений владельца сначала сохранить полученный материал в текстовый файл и ссылаться на него. `example` — только учебные данные.

Снимок дополняется `file` (отображаемый адрес), `fileHash` (SHA-256 исходного файла), `sha`, `local`, `url`. При изменениях относительно HEAD ссылка на коммит не подменяет локальный файл: выводится локальный снимок. GitHub-ссылки формируются только для совпадающего с HEAD содержимого и известного origin. В автономном снимке допускается HTTPS-ссылка на иной проверенный источник.

`redact: true` скрывает фрагмент; `note` объясняет причину. Значения секретов не должны попадать ни в модель, ни в тексты элементов. Сборщик сам требует скрытия `.env`, `.pem` и `.key`; другие чувствительные данные определяет агент.

Обычно достаточно 5–80 строк на одно основание. Длинный файл разделить на конкретные места и сослаться на несколько id.

## views

Обязательные: `title`, `description`, `gaps`, `layers`, `nodes`, `edges`.

- `description` — о чём эта карта и какой сценарий объясняет.
- `gaps` — пределы анализа. Даже при полном разборе кода уточнить, проверялось ли работающее окружение.
- `layers` — названия горизонтальных слоёв сверху вниз, непустой массив.
- `short` — короткое название в каталоге; по умолчанию `title`.
- `group` — группа в каталоге; по умолчанию «Карты».
- `icon` — необязательное имя значка; неизвестное имя заменяется значком сети.
- `finding` — необязательное важное пояснение. Основания для него должны быть раскрыты в элементах схемы.
- `related` — id других представлений для перехода из обзора.

Порядок карт и групп соответствует порядку в JSON. Вычисляемые количества берутся из `nodes` и `edges`.

### Узлы

```json
{
  "id": "check-access",
  "title": "Доступ разрешён?",
  "type": "decision",
  "row": 0,
  "col": 1,
  "description": "Неактивному пользователю обработчик отказывает до создания задания.",
  "source": ["submit-handler"],
  "certainty": "verified",
  "symbol": "submit_report",
  "repo": "backend"
}
```

`type`: `entry`, `service`, `step`, `decision`, `data`, `event`, `success`, `error`, `external`.

`row` — индекс слоя с нуля; `col` — колонка с нуля. В ячейке один узел. Размер холста вычисляется по слоям и колонкам, `fit` показывает всё. Для чтения без постоянного увеличения предпочитать до 3 колонок и 4 слоёв; большие области делить на связанные карты.

`source` — id или массив id оснований. У факта (`certainty: verified`, значение по умолчанию) нужен минимум один источник. Для `inferred` и `unknown` обязателен `gap` с конкретным объяснением. Они получают пунктир и явную пометку; основания могут отсутствовать.

Необязательные поля: `scenario` — id вложенной карты; `symbol` — имя функции/типа из кода; `repo` — название источника для инспектора и поиска; `objects` — короткий перечень существенных данных.

Одна реальная сущность может быть показана в разных представлениях с разной глубиной. Сохранять смысл имени и техническую идентичность; id адресуется парой `view/id`.

### Связи

```json
{
  "id": "enqueue",
  "from": "handler",
  "to": "queue",
  "label": "публикует задание",
  "description": "После записи отчёта обработчик добавляет его id в очередь.",
  "source": "submit-handler"
}
```

Обязательны `id`, `from`, `to`, `label`, `description`, а также основание либо явно отмеченная граница по тем же правилам, что у узла. Оба конца находятся в этой карте. Вложенные карты открываются через узлы, а не через оборванные стрелки между холстами.

`lane`: `auto` (по умолчанию), `left`, `right`, `top`, `bottom`. Боковые пути подходят для обхода промежуточных рядов и циклов; верхний и нижний — для связи вдоль края. `labelDx`, `labelDy` сдвигают подпись в координатах холста. Настраивать после осмотра, когда подписи пересекаются или связь читается неоднозначно.

## Проверка и повторная сборка

`--check` проверяет структуру и доступность оснований, ничего не записывает. С `--root` точные фрагменты извлекаются заново; без него для каждого источника требуются сохранённые `code` и `fileHash`. Сборка пишет HTML и JSON с одинаковой основой имени. Входной JSON не перезаписывается. Для обновления снимка использовать другое выходное имя либо сохранить входную модель в отдельной папке `data/`.

Хеши и диапазоны обеспечивают происхождение фрагментов. Они не заменяют повторного исследования поведения при изменениях проекта. Перед публикацией проверить текст модели и приложенные фрагменты на чувствительные данные.
